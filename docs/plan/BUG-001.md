# BUG-001 — Fix hard-coded size constraints in controls

## Objective

Make hard-coded, non-overridable size constraints in reusable controls configurable via backward-compatible `StyledProperty` members, so consumers can define wider/taller content. Reported against `ContentDialog` (width capped at 600px); the same class of whole-control cap exists in `NavigationView` and `NavigationItem`.

## Scope

- **In:** `ContentDialog` (width + height), `NavigationView` (rail size), `NavigationItem` (label max width).
- **Out:** `CalendarSchedule` (fixed sidebar/gutter/hour-height are woven through layout & event-positioning math — internal detail, not the reported problem).

## Design

- All new sizing is exposed as `StyledProperty<double>` members `TemplateBound` into the control templates, with **defaults equal to today's values** so existing consumers see zero visual change (purely additive API).
- `ContentDialog`'s outer control stays `Stretch` (it paints the full-window overlay), so inherited `MaxWidth`/`Width` cannot be reused for the card — dedicated `Dialog*` properties are used instead.
- One-way template bindings use `{TemplateBinding X}` in `ControlTemplate` scope and `{Binding X, RelativeSource={RelativeSource TemplatedParent}}` in `Style` setters (per CLAUDE.md).

## Acceptance criteria (whole item)

- Existing dialogs, nav rail, and nav items render identically with defaults.
- Consumers can make dialogs wider than 600px, control dialog height with tall content scrolling, resize the nav rail, and widen nav item labels.
- Build succeeds with zero warnings; manual verification via the tester app passes.

---

## PHASE01 — ContentDialog width/height config

**Status:** DONE — verified via tester app: Wide Dialog renders ~845px (DialogMaxWidth=900); Tall Dialog scrolls content within the card with title/buttons fixed (DialogMaxHeight=400).

### Steps
1. `Controls/ContentDialog/ContentDialog.cs` — add six `StyledProperty<double>` + CLR wrappers: `DialogWidth` (NaN), `DialogHeight` (NaN), `DialogMinWidth` (320), `DialogMaxWidth` (600), `DialogMinHeight` (0), `DialogMaxHeight` (PositiveInfinity), each XML-documented.
2. `Themes/Controls/ContentDialog.axaml` — on the card `Border`, replace literal `MinWidth`/`MaxWidth` with `TemplateBinding`s and add `Width`/`Height`/`MinHeight`/`MaxHeight` bindings; wrap the `Grid.Row="1"` content region in a `ScrollViewer` (vertical Auto, horizontal Disabled).
3. Tester — add `ShowWideDialogCommand` to `ServicesTestingPageViewModel` (sets `DialogMaxWidth` ~900 with wide content) and a "Show Wide Dialog" button in `ServicesTestingPageView.axaml`.

### Acceptance criteria
- Existing simple/complex/password dialogs render identically.
- Wide-dialog demo renders content wider than 600px.
- Tall content scrolls within the card; title + buttons stay fixed.
- Zero-warning build.

## PHASE02 — NavigationView / NavigationItem size config

**Status:** DONE — verified via tester app: vertical `PaneSize` widens the rail (90→150); horizontal `PaneSize` caps rail height via the style-setter binding (60 clamps vs 130); `LabelMaxWidth` widens item labels (wraps at 160). The code-behind fallback was not needed. Adversarial multi-lens review raised only two `low` doc-accuracy findings, both fixed in `ReleaseNotes.md` (scroll-behavior wording; pre-existing Cobalt→Carbon typo).

### Steps
1. `Controls/Navigation/NavigationView.cs` — add `StyledProperty<double> PaneSize` (default 90) + CLR wrapper.
2. `Themes/Controls/Navigation/NavigationView.axaml` — root `Border#PART_Border` `Width` → `{TemplateBinding PaneSize}`; horizontal style `MaxHeight` → `{Binding PaneSize, RelativeSource={RelativeSource TemplatedParent}}` (keep `Width="NaN"`).
3. `Controls/Navigation/NavigationItem.cs` — add `StyledProperty<double> LabelMaxWidth` (default 72) + CLR wrapper.
4. `Themes/Controls/Navigation/NavigationItem.axaml` — horizontal style `MaxWidth` → `{Binding LabelMaxWidth, RelativeSource={RelativeSource TemplatedParent}}`.

**Fallback:** if a `RelativeSource=TemplatedParent` binding inside a `Style` setter does not resolve at runtime, drive `MaxHeight`/`Width` from `OnApplyTemplate`/`Orientation` in code.

### Acceptance criteria
- Defaults: rail 90px, item labels cap 72px — identical to today.
- Setting `PaneSize` resizes the rail (both orientations); `LabelMaxWidth` widens labels.
- Zero-warning build.
